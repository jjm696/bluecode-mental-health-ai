# 面试问答最终稿

## 1. 先用一句话介绍项目

这是一个 AI 心理健康助手系统，分为用户端和后台管理端两部分，用户端负责 AI 咨询、情绪日记和知识库使用，后台端负责文章管理、咨询记录查看、情绪日志复核和数据分析，后端采用 Spring Boot + MyBatis + MySQL，前端采用 Vue3。

## 2. 这个项目为什么不只是普通聊天项目？

因为它不是只做了一个对话框，而是围绕“用户表达情绪、AI 给出陪伴式回复、系统保存结构化数据、后台进行复核与管理”形成了完整闭环。项目里有用户端、后台端、数据库建模和管理逻辑，已经接近一个真实产品系统。

## 3. 你在项目中最核心的工作是什么？

我做的最核心工作有三块：

- 设计数据库模型，把文章、咨询会话、咨询消息、情绪日志、AI 分析结果这些核心实体拆清楚
- 用 Spring Boot + MyBatis 实现后端接口，包括登录鉴权、文章管理、分页查询、消息落库
- 用 Vue3 完成用户端和后台管理端双端页面，并接入真实后端与 DeepSeek 对话能力

## 4. 为什么后端选 Spring Boot + MyBatis + MySQL？

因为这个项目有比较明确的结构化数据和后台管理需求，比如文章筛选、分页查询、咨询记录查看、情绪日志复核、统计分析等，这类场景更适合关系型数据库。Spring Boot 适合快速搭建接口层，MyBatis 更适合我手写 SQL、控制查询结构和分页逻辑。

## 5. 数据库是怎么设计的？

我把核心数据拆成了这些表：

- `users`：普通用户
- `admins`：管理员
- `knowledge_articles`：知识文章
- `article_categories`、`article_tags`、`article_tag_relations`：文章分类和标签体系
- `consultation_sessions`：咨询会话摘要
- `consultation_messages`：咨询消息明细
- `emotion_logs`：情绪日记
- `emotion_ai_analyses`：情绪分析结果

这样拆的原因是为了把会话摘要和逐条消息分开，把日志内容和 AI 分析结果分开，后续查询、统计、扩展都更清晰。

## 6. AI 咨询是怎么接入的？

前端不会直接调用大模型，而是请求 Spring Boot 后端。后端做几件事：

1. 接收用户消息
2. 根据当前用户查找或创建咨询会话
3. 把用户消息先写进数据库
4. 组织系统提示词和历史消息，请求 DeepSeek 兼容接口
5. 把 AI 回复写进数据库
6. 返回给前端显示

这样做的好处是不会暴露 API Key，也便于做会话管理、日志记录和提示词控制。

## 7. 你是怎么让 AI 更像心理健康助手，而不是普通聊天机器人？

我在后端的系统提示词里专门约束了回复风格，比如要求：

- 优先共情，接住情绪
- 不直接说教，不像客服
- 对“累、焦虑、难受、委屈、压力大”这类表达优先帮助用户展开
- 用开放式问题引导用户继续说
- 如果检测到高风险表达，要优先提醒现实求助和安全支持

同时我还做了场景识别，根据用户输入判断更接近疲惫压力、焦虑紧张、低落悲伤、关系冲突还是高风险场景，再动态拼接不同的引导策略。

## 8. 后台咨询记录除了显示消息，还有什么价值？

我不仅保存消息文本，还会把 AI 对当前轮输入的分析结果结构化回写到会话表里，比如：

- 主要情绪 `dominant_emotion`
- 风险等级 `risk_level`
- 摘要建议 `summary`

这样后台管理员看到的不是原始聊天记录堆叠，而是带有结构化线索的咨询记录，更方便筛查和复核。

## 9. 用户端和后台端为什么要做登录态隔离？

因为用户端和后台端是两个不同身份体系。为了避免一个标签页里同时持有两种身份造成混乱，我把登录态改成了基于 `sessionStorage` 的标签页隔离，并约束同一标签页中只能存在一种身份。如果要同时登录用户端和后台端，需要另开新标签页。

## 10. “数据实时同步”是怎么做的？

我目前用了轮询而不是 WebSocket。像后台数据分析、咨询记录、情绪日志，以及用户端“我的记录”页，会定时重新拉取接口，这样用户端新增咨询或情绪记录后，后台端和记录页不需要手动刷新，几秒后就能看到更新。这种方式实现成本低，足够满足当前项目演示需求。

## 11. 这个项目的难点是什么？

难点主要不是页面，而是业务抽象和边界控制：

- 怎么把聊天、情绪记录、文章内容、后台管理放进同一个系统而不混乱
- 怎么设计数据库让会话和消息、日志和分析结果、文章和标签之间的关系清晰
- 怎么让 AI 回复更像心理陪伴，而不是泛化聊天
- 怎么在用户端和后台端之间建立近实时的数据同步体验

## 12. 如果继续做，你会怎么扩展？

- 增加真正的个人中心和用户档案
- 给后台加角色权限控制
- 对情绪日记和咨询记录做图表趋势分析
- 接入更细粒度的风险识别和干预策略
- 用 WebSocket 替代轮询，做真正实时同步

## 13. 面试官如果问“这个项目最大的亮点是什么”，怎么答？

我认为最大的亮点是它不是一个单页面 Demo，而是一个前后台双端、带 AI 会话、带数据库建模、带后台管理、带近实时同步的完整系统。它同时能体现前端工程能力、后端接口设计能力、数据库建模能力和业务闭环思维，这比单纯做聊天页面或后台表格更有含金量。
