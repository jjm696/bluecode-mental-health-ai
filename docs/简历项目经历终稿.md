# 简历项目经历终稿

## 项目名称

AI 心理健康助手

## 技术栈

Vue3、Vite、Vue Router、Pinia、Element Plus、Spring Boot、MyBatis、MySQL

## 简历版项目描述

### 版本一：适合直接放简历

独立完成 AI 心理健康助手前后台双端项目开发，前端基于 Vue3 + Element Plus 搭建用户端与后台管理端，覆盖 AI 咨询、情绪日记、知识库阅读、文章管理、咨询记录查看、情绪日志复核与数据分析等模块；后端基于 Spring Boot + MyBatis + MySQL 完成用户、文章、咨询会话、情绪日志及 AI 分析结果等数据建模，实现登录鉴权、文章增删改查、会话消息落库和多业务分页查询，形成前后端联调闭环。

### 版本二：稍短版

负责开发 AI 心理健康助手项目，使用 Vue3 实现用户端和管理后台，完成 AI 咨询、情绪记录、知识库浏览及后台文章、咨询、情绪日志管理；后端采用 Spring Boot + MyBatis + MySQL 实现登录鉴权、数据建模、分页查询与核心业务接口。

## 可拆成的简历要点

- 设计并实现 AI 心理健康助手前后台双端架构，覆盖用户咨询、情绪记录、知识库管理和后台风险复核流程
- 基于 Spring Boot + MyBatis + MySQL 完成用户、知识文章、咨询会话、咨询消息、情绪日志、AI 分析结果等核心表结构建模
- 实现管理员登录鉴权、文章新增/编辑/删除、详情预览、多业务分页查询等后台核心功能
- 实现用户注册/登录、情绪日记落库、AI 咨询会话落库、历史会话管理及个人记录展示
- 接入 DeepSeek/OpenAI 兼容格式的 AI 会话调用链路，支持真实模型回复与本地兜底回复切换

## 面试追问终稿

### 1. 这个项目的核心价值是什么？

它不是单一聊天页，而是一个前后台闭环系统。用户端负责输入情绪、发起咨询、阅读知识内容，后台端负责文章运营、咨询记录查看、情绪风险复核和数据分析，目的是把陪伴式 AI 对话和结构化管理结合起来。

### 2. 为什么这个项目适合写进简历？

因为它同时覆盖前端页面组织、后端接口分层、数据库建模、登录鉴权、分页查询和 AI 会话接入，比单纯的管理系统或静态展示项目更有完整度，也更容易体现业务理解。

### 3. 数据库为什么这样拆？

我把文章和标签拆表、咨询会话和消息拆表、情绪日志和 AI 分析拆表。这样做的原因是：

- 降低耦合，避免一个表承担过多字段和职责
- 更适合后续做分页查询、统计分析和关系扩展
- 更方便后面替换模型或重复分析

### 4. 你做了哪些有代表性的后端功能？

- 管理员登录鉴权
- 用户登录注册
- 文章增删改查
- 咨询会话与消息落库
- 情绪日记与 AI 分析结果落库
- 多业务分页查询

### 5. AI 会话是怎么接的？

前端不会直接调用模型，而是请求 Spring Boot 后端。后端负责：

- 接收用户消息
- 查找或创建会话
- 保存用户消息
- 调用 DeepSeek/OpenAI 兼容接口生成回复
- 保存 AI 回复
- 返回给前端显示

如果没有配置真实 API Key，则走本地兜底回复，但会话仍然会落库，便于前端联调和演示。

### 6. 这个项目目前还有哪些可继续扩展的点？

- 真正做用户个人中心
- 接入更完整的 AI 风险评估策略
- 给情绪日记增加趋势图
- 给后台加角色权限控制
- 引入文件上传和富文本编辑器

## 一分钟自我表达版本

我做了一个 AI 心理健康助手项目，前端采用 Vue3，后端采用 Spring Boot + MyBatis + MySQL。它不是单一聊天页面，而是包含用户端和后台管理端两部分。用户端支持 AI 咨询、情绪日记和知识库阅读，后台端支持文章管理、咨询记录查看、情绪日志复核和数据分析。项目里我重点做了数据库建模、登录鉴权、分页查询、文章增删改查，以及 AI 会话的落库和接口接入，因此这个项目比较适合放在简历中体现我对业务闭环和前后端联动的理解。
